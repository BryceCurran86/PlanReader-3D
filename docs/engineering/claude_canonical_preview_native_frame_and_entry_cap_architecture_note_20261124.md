## 1. Observed repository behaviour (main 21340b16b, real originals read in place, counts only)

**1.1 One rectangle, two frames.** `source_native_trace_preview` reads `rect = page.rect`, the DISPLAYED rectangle, and uses it three times: the tiles (`_full_page_source_tiles(rect.width, rect.height, len(drawings))`, `pb_new_source_trace_preview.py:261`), the canvas (`new_page(width=rect.width, height=rect.height)`, `:294`) and the background (`show_pdf_page(canvas.rect, document, page_index)`, `:295`). Every `get_drawings()` row, strip, ring polygon, closure box and overlay coordinate is in the page's NATIVE frame (#4652 documents this and cross-checks it against PyMuPDF's own matrix). On a /Rotate 90 or 270 page the display extent is the native extent transposed.

**1.2 What that does on a real rotated sheet** (Maryborough page 25, /Rotate 90, display 2384 x 1684, native 1684 x 2384). The tiles cover native y in [0, 1684] only and the canvas crops at the same line. The background (`show_pdf_page` with the display rectangle) is also wrong: it shows that native region unrotated, so the picture is turned 90 degrees against what any viewer shows. 1,663 of 12,738 wall-support primitives, 13 of 57 opaque-fill primitives and 3,916 of 4,637 doorway/glazing evidence primitives lie outside the tiles (5,592 of 17,432 counted primitives, the same difference the cap check shows between columns A and B below). The sheet's plan view, with its doors and windows, is in the lost band: the ring stage works on the elevation drawings only (2 rings, 4 closures) and the PNG the UI shows has no plan on it. Rendered with native-extent tiles, a native-size canvas that carries the page's /Rotate and an unrotated background (scratch, 3 lines), the PNG is complete, upright and aligned with the overlays, and the plan is traced (72 strips, 2 rings, 5 closures). Both PNGs were inspected locally; nothing is committed.

**1.3 Corpus (61 PDFs, 861 pages, local).** 166 pages are /Rotate 90 (none is 180 or 270; the first scan lumped 90 and 270, the seam census in section 8 separates them): Maryborough 29 of its 31 pages and seven public sample PDFs (every page of each of them). On those pages 478,330 of 1,493,394 rows (32%) lie outside the displayed rectangle; 161 of the 166 pages have some; the worst page has 89%. The other 695 pages are upright, where the display and native extents coincide. So this is a general preview defect, not a Maryborough one.

**1.4 The preview's entry cap.** The builder the preview calls (`pb_next_wall_ring_preview.build_layered_wall_doorway_room_rings`, viewport-aware, stroke-pair mode) counts EVERY item inside the viewport union (`_selected_primitive_count`, `:308-320`; entry checks `:2260-2304`). Above 20,000 it builds per tile and merges (`_merge_ring_results`, `:2131-2175`, which carries rings, closures and counts only and silently drops the cap reason of a tile that abstained). The rows include the doorway/glazing evidence strokes the selector retains since `3ce1d9b18`. The stroke-pair collector cannot use them: `_axis_strokes` (`:558`) takes only unfilled strokes whose colour is `None` or neutral dark (`_is_wall_stroke_color`, `:553`). On all five pages measured, 0 of the evidence-role primitives have such a colour, so the count the collectors can consume equals P1's structural count.

**1.5 Door chords.** The layered builder wires the two segmented-door producers behind `dark_painted_wall_source` (`pb_layered_wall_doorway_room_ring_shadow.py:2271-2304`: `collect_source_black_segmented_door_swings`, then `propose_source_owned_doorway_chords`). The preview builder has no such producer, its swing detector reads native curves only, and its result type (`LayeredRoomRingResult`, `:255`) has no chord, witness or two-wall-tag field at all, so P2c would also extend that type (additive, empty by default). Every closure it makes on these pages is a `source_stroke_closure` (0 `swing_doorway`, 0 chords, with or without native tiles; measured earlier with a closure-kind spy on the same code). The proposer needs, per witness, wall-end strokes and perpendicular jamb strokes on BOTH sides and exactly one raw wall gap that contains the swing interval and has an end within 0.18 pt of it. Measured on the post-`4285e133a` tree: the segmented producer finds the black-polyline doors (A110 12, A500 4, A501 2, A502 1, A503 2 witnesses) but the nearest same-line gap misses by 0.6 to 4.56 pt on A500-A503, so 0 chords; A110 had 2 chords at `e93dbfe2e` and has 0 since `4285e133a`. ## 2. Inference

1. The frame defect is independent of chords and of the cap: it hides the plan view on every rotated sheet, and the A501 plan holds the doors and windows. It needs no threshold and no new authority, only the page's native extent, and it is byte-identical on upright pages by construction.
2. The extent of a /Rotate 90 page in the native frame is the display extent transposed, and the repository already has the sanctioned seam for it, `pb_native_page_frame.native_page_frame` (found after this note was first written; see section 8). Every coordinate in the preview is already native, so no conversion is needed and P2a depends on neither #4652's matrix nor a new helper. (A validated matrix would only matter if a caller handed in display-frame viewports; that contract is stated in D6.)
3. Draw in the native frame, render in the display frame: a canvas that carries the page's /Rotate shows native-coordinate overlays upright and aligned (verified on a real page). The overlay code (about forty draw calls) stays untouched.
4. The entry cap in the preview has the same flaw as the layered cap had before P1, but it is not P1's rule: the preview's collectors do consume neutral-dark unfilled strokes, which P1's role function calls evidence. The faithful definition is "rows the collectors cannot consume": evidence-role rows whose stroke colour is not a wall-stroke colour. On every measured page it equals P1's count, and it stays correct on a CAD export with dark-grey walls.
5. Door chords cannot appear in the preview until BOTH a producer exists in that builder and the layered builder produces chords on a real page. The second needs a gate analysis (and the `4285e133a` regression), not a looser tolerance. So wiring the producers first would add code that no real page can exercise.

## 3. Proposed change (shadow, no new authority), three independent PRs

**P2a: preview frame (`pb_new_source_trace_preview.py` only).** The frame comes from `pb_native_page_frame.native_page_frame(page)` (read-only reuse). Tiles from its `native_width` and `native_height`; canvas `new_page(width=native_width, height=native_height)` then `canvas.set_rotation(frame.rotation)`; for a rotated page the in-memory source page's rotation is reset to 0 just before `show_pdf_page(Rect(0, 0, native_width, native_height), document, page_index)` (the document is a local stream; nothing is saved, the source bytes and hash are untouched). A /Rotate 180, 270 or unreadable frame is not promoted by the seam, so the call raises `ValueError("new_trace_native_page_frame_unresolved")` before any tracing instead of running in the wrong frame. On an upright page every argument is unchanged. The summary gains, on rotated pages only, the seam's own `native_page_frame` receipt (the key and fields the diagnostics already use) and `preview_png_orientation: "displayed"`; an upright page's summary is byte-identical. Rings, closures and strips on rotated pages change on purpose (they now see the whole page).

**P2b: entry count (`pb_next_wall_ring_preview.py` only).** One function, `_entry_primitive_count`, counts every item except those on evidence-only rows (`_source_wall_ink_role(row) == "evidence"` and `not _is_wall_stroke_color(row["color"])`), used at the three builder entry checks (`:2262`, `:2287`, `:2300`). Same 20,000, same reason code. Evidence rows stay in the clipped rows with their original path indices for every closure search. The halo functions (`_clip_if_under_cap`, `_largest_halo_under_cap`, `expand_labelled_stroke_pair_viewports`) keep counting everything: they bound a different, local neighbourhood and their callers are outside this change. Independent of P2a; either may merge first.

**P3a (measurement first, then P2c).** Export, from `propose_source_owned_doorway_chords`, the first failing gate per segmented witness (which support set is empty, parent gaps 0 or 2+, the end miss in pt) as a measurement-only receipt; find the `4285e133a` change that took A110's two chords; only then decide a principled fix. **P2c** (default-off producers in the viewport-aware builder, and a merge that keeps chords, witnesses and path ids and surfaces the cap reason of a dropped tile) follows once a real page produces chords in the layered builder; before that its only real-data result would be zero.

## 4. Tests

**P2a (synthetic, no private data):** a /Rotate 90 and a /Rotate 270 page, non-square, with and without /UserUnit 2 and a crop box, whose room lies entirely in the band the old tiles missed: old code finds no strips, new code closes the ring. Rotation invariance: the same native content on /Rotate 0 and 90 gives identical summaries (the source digest masked) and tile boxes; 180 and 270 fail closed with the typed error before any tracing. Upright invariance: summary and PNG digests of upright synthetic pages equal the pre-change digests (frozen in the test). Overlay alignment: the overlay colours land on the wall pixels of the same rendered page within one pixel on every rotation. The source bytes and hash do not change; deterministic replay; no input mutation; the route guard and the existing preview tests pass unchanged; single-line mutants for the extent swap, the canvas rotation, the background reset and the guard `if page.rotation`.

**P2b (synthetic):** exactly 20,000 consumable primitives run and 20,001 tile or abstain, with and without 50,000 evidence primitives; a 25,000-row evidence flood before an in-budget wall set still closes the room with original indices; evidence rows with a wall-stroke colour DO count (look-alike negative); an over-budget consumable set still tiles or abstains; a differential against the old count on evidence-free inputs (identical decisions and results); the halo functions give identical results on their fixtures; translation, viewport-expansion and unrelated-content invariance; no mutation; mutants.
