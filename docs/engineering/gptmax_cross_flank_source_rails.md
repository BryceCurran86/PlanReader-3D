## Original flank-locality integrity review

**Observed:** `inspect_cross_flank_rails` validates the source digest and
parallel source-run direction but `_side_candidates` trusts the JSON's left
or right label. A remote parallel line, a line on the opposite side or one
crossing the aperture can retain matching normal offsets and form a reported
four-rail alternative. `full_foreground_flank_census` already checks actual
G17 face/end contact, but that check is not independently repeated here.

**Inference:** altered intermediate reports can falsely describe remote ink
as a local flank opportunity even though all host/publication flags stay false.

**Proposed:** reconstruct both required flanks from the original six G17
source-owned face/end receipts using `_reported_flanks`; repeat the existing
endpoint, normal-band and positive interval-overlap predicates in
`_side_candidates`. Keep every qualifying alternative and reject any reported
run that violates its own original flank. Do not add a tolerance or infer
structural role, physical equivalence or host authority.

Missing/foreign G17 support, swapped sides, remote geometry, aperture-crossing
ink and out-of-band lines must abstain. Reversal, translation, rotation and
input permutation must preserve valid opportunities. Original project IDs,
seven cases and observed rail counts are source-run controls only. Production
modules, PDFs, quantities, frozen V2 and the input safety bound stay untouched.
