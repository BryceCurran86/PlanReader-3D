# Native legend word recognition shadow — 11 November 2026

The genuine original Office floor attempt on9a resolved room area and cross-sheet correspondence, then abstained because the material occurrence and definition were unavailable. The existing material publisher routes legend word crops through its ordinary raster publisher, while the opted-in physical-plan word recognition path had only been applied to drawing words. Both paths render a producer-owned native word, but the legend path was still running the page text detector.

Added an explicit `for_native_word_recognition_shadow` raster factory. It uses RapidOCR's existing recognition-only call for the isolated word and preserves ordinary glyph-integrity admissibility. It does not admit clip-only receipts. The existing physical-plan factory retains its separate clip policy. The ordinary default factory and its configuration/record IDs retain detector behavior. The changed inference configuration is included in the existing backend-version proof payload, producing separate proof IDs.

The source material publisher selects this legend mode only when already configured for source-owned physical-plan pages. Its source-owned cache is separated by inference mode and rechecks source identity, exact producer class and both policy flags. No process-global/cross-source material cache, native receipt modification, retry/fallback after a failed reading or native claim supplied to OCR is introduced. Two independent renders, exact native agreement, confidence, competing text, image geometry, source hash, revision and lineage gates remain active.

Validation: thirteen new tests initially failed before the change; 136 combined new/existing raster/material tests then passed. With one additional cross-source cache regression, all14 new tests passed. A private unmodified-original probe found six native FT3 words on page11; all six were independently corroborated by the real selected OCR backend under the strict legend mode. This establishes word evidence only; finish ownership, quantities, customer results and benchmark matches still require their existing source pipeline. Final head source/customer acceptance and full Python3.13/3.14 CI are separate release requirements.
