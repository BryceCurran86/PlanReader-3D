## #2813 - NOT yet recommendable; one blocking ask and one process gap
What changes in the flag-on path: the "aligned fragment must be proven DISTINCT" check is skipped for a wall that a new census (`repeated_raster_drafting_motif_wall_ids`) calls a repeated drafting motif, if the host component member is not itself in the motif set and the pair has no stored identity relation. I probed the census directly (snippet in the collapsed block at the end; it only calls the new pure function) and it does not meet the AGENTS.md required-test list as written:
1. **Not viewport-expansion invariant.** The motif threshold is `0.03 x page_span`, and `page_span` comes from the scope's viewport bbox. The same eight 4.5 pt raster ticks are a motif family at `page_span` 150 and above and **not** at 100: spans 100 -> 0 motif walls; 150, 151, 1000, 5000 -> 8. So adding unrelated sheet content around the viewport can turn a fail-closed frame into a shadow-accepted one. (Uniform scale of geometry and span together is invariant: 8/8/8 at 0.5x, 2x, 10x.)
2. **Population statistic, not per-candidate evidence, and no look-alike negative.** Eight identical collinear 28 pt pieces (what a real wall split by openings can look like) are all classified as a motif (8/8). They are only protected if a component member shares their length signature; a differently sized host component would let them be skipped, and the frame's whole-wall extent would then silently exclude real wall. Seven identical pieces, or eight with one different, correctly give 0, so the boundary is exactly the `REPEAT_MIN = 8` constant. The tests include "seven ticks abstain" and "unique fragment abstains" but nothing at 8 or more genuine fragments.
3. Jitter below 0.01 pt still counts as the same signature (`round(length, 2)`), harmless but worth a test so the tolerance is deliberate.
4. `_span_from_rect` uses an unexplained `0.05` aspect threshold to decide whether the viewport is "1-D"; please name it and say where it comes from or reuse an existing constant.

import sys
sys.path.insert(0, ".")
from types import SimpleNamespace
from pb_physical_wall_candidate_authority import repeated_raster_drafting_motif_wall_ids as motif

def rw(i, x1, y1, x2, y2):
    return SimpleNamespace(wall_candidate_id=i, wall_candidate=SimpleNamespace(centerline_pts=((x1, y1), (x2, y2))),
                           physical_identity=SimpleNamespace(source_primitive_ids=(f"raster_segment:s:1:{i}",)))

def fam(n, length, pitch, y=10.0, x0=0.0):
    return [rw(f"w{k}", x0 + k * pitch, y, x0 + k * pitch + length, y) for k in range(n)]

# 1. viewport expansion: same 8 ticks, page span 100 -> 1000 -> 5000 (an unrelated sheet region added)
ticks = fam(8, 4.5, 20.0)
print("viewport span -> motif count:", {s: len(motif(ticks, page_span=s)) for s in (100.0, 150.0, 151.0, 1000.0, 5000.0)})
# 2. uniform scale of geometry AND span: invariant?
for k in (0.5, 2.0, 10.0):
    sc = [rw(w.wall_candidate_id, *(c * k for c in (w.wall_candidate.centerline_pts[0] + w.wall_candidate.centerline_pts[1]))) for w in ticks]
    print("scale", k, len(motif(sc, page_span=1000.0 * k)))
# 3. 8 identical collinear genuine wall pieces (e.g. a corridor wall split by openings), 3% of a 1000 pt page = 30 pt
