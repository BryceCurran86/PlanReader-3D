## 1. Observed repository behavior

1. **The test.** `classify_native_path_role` (lines 105 to 115), after the green, dashed and excluded-layer returns and before the diagonal and owner checks: when `page_bounds` is passed, a row is `ROLE_EXCLUSION` if `row["rect"].y1 >= y0 + 0.82 * (y1 - y0)` of those bounds. It tests the row's lowest edge only, so a row that starts above the band and ends inside it is excluded whole. With `page_bounds=None` there is no test.
2. **Two spaces.** `row["rect"]` comes from `page.get_drawings()`: NATIVE (unrotated, crop-origin, UserUnit-scaled) space. The only non-test caller, `tools/run_native_exterior_path_ownership.py` lines 75 to 86, passes `page.rect`: DISPLAY (rotated) space. Upright, they are the same space and the test means "the lowest 18 percent of the sheet". At /Rotate 90 it compares native y with the display height.
3. **What that excludes at /Rotate 90.** A native point (x, y) displays at (h - y, x) (`pb_page_frame_shadow.native_to_display`; checked here against `page.rotation_matrix` at all four rotations on a synthetic page). So the displayed lowest edge of a row is its native `x1`, and the display height is the native width. The code instead tests native `y1` against 0.82 times the native width: on a native-portrait sheet (short side w, long side h) it excludes native y >= 0.82 w, which is the left `1 - 0.82 (w / h)` of the displayed width (42 percent for an ISO-proportioned sheet), and it never looks at the real band (native x >= 0.82 w). On a native-landscape sheet at /Rotate 90 whose long side exceeds 1.22 times its short side (every ISO and ANSI size) the threshold lies beyond the page, so nothing is excluded and the real band is missed.
4. **Consumers.** `classify_native_path_role` is called only by `identify_source_wall_junctions_and_roles`, whose importers are `tools/run_native_exterior_path_ownership.py` (also launched by `tools/run_antigravity_wall_closure.ps1`) and tests. No production module imports `pb_source_native_wall_role_and_junction_shadow`. The face-walk, wall-body-graph and outer-house-continuity shadows use a different classifier, `classify_source_native_path_role` in `pb_source_native_exterior_endpoint_authority_shadow.py`, which has no title-band test (two classifiers with the same role constants).
5. **Other title-band literals (same idea, three places).** (a) `trace_external_footprint_first` zeroes the lowest 18 percent of the displayed raster and rejects a candidate whose `y + h > 0.82 * height` (lines 158 and 182): display-space on a display raster, consistent. (b) this classifier. (c) `refuse_title_block_as_walls` takes a caller-supplied bbox and bounds and a 0.18 fraction, no row data. Only (b) mixes spaces.
6. **Existing frame seams.** `pb_native_page_frame.effective_pdf_rotation(page)` / `native_page_frame(page)` is the production contract: rotation 0 and 90 supported, 180 and 270 raise `NativePageFrameUnresolved` until real files pass their gate; five production modules import it (viewport segmentation and the physical-wall-candidate, plan-view, observation and raster plan-dimension authorities). `pb_page_frame_shadow` is the canonical vocabulary, but `test_no_production_module_imports_the_page_frame_shadow` forbids any module outside `tests`, `benchmarks` and `scripts` from importing it (and one test pins its single script importer), so the role module and the tool cannot use it. #4652 (Draft) adds `ExternalFootprintTrace.page_derotation_matrix`, set only on CANDIDATE traces (`_abstain` does not carry it).
7. **Measured on the 58 local original PDFs (702 pages; 129 rotated pages, all /Rotate 90 and native-portrait; counts only, not a protected run).**
   - Path rows on the rotated pages: 1,353,356. Today's test flags 764,990 (56.5 percent). The same test in display space flags 32,817 (2.4 percent); 14,264 rows are flagged by both. 750,726 rows (55.5 percent) are excluded today and are not in the displayed band; 18,553 rows in the real band are missed. All 129 pages differ; on the median page 44.9 percent of rows are wrongly inside today's band.
   - Role effect of this test alone: 695,019 rows labelled `exclusion_site_roof_hatch_title_green` would be `unknown`, 23,744 would be `rejected_diagonal_bridge`; 17,090 `unknown` and 1,461 diagonal rows would become exclusions. Status is ABSTAINED either way: none of these rows is on a layer that `is_explicit_wall_layer_name` accepts.
   - Rows that own the traced exterior contour (the rows that would be `exterior_outer_face_candidate`), computed on the #4652 head: 116 rows on 26 pages. Today's test labels 59 of them `exclusion` (ABSTAINED); the display-space test labels 12; so 47 fewer rows would be `exclusion` and `exterior_outer_face_candidate` would rise from 55 to 100 rows (**corrected in section 8**: this first draft said "47 rows on 19 pages would be exterior"; 51 rows leave exclusion and 4 enter it, 45 become exterior candidates and 2 diagonal bridges, and the labels differ on 19 pages in all). On `main`, where ownership is still computed in mixed spaces, only 8 owner rows exist (7 pages), so this test is not yet the first blocker there. Owners were computed without ring closures (an approximation of the tool).
   - Upright control (checks the measurement itself): 99 upright pages (325,763 rows): the display-space test equals today's test on every row.
8. **No test covers a rotated page** for this classifier; its one title test uses an upright 400 x 800 page.

## 2. Inference

- Same defect class as #4652, different carrier: here the caller's `page_bounds` is display space while the rows are native, and nothing in the signature says so, so every caller silently assumes upright.
- Nothing commercial depends on it: the role report is diagnostic. The consequence is a systematically wrong `role_counts` and owner-role report on rotated sheets, and it becomes the main remaining thing hiding exterior-contour ownership once #4652 lands (51 of the 116 owner rows are wrongly excluded today and 4 in the real band are missed; section 8).
- A silent skip would be the wrong repair: on a page whose frame cannot be established, title-block rows would then be free to take a positive role. The test must either be evaluated in the right space or abstain.

## 3. Proposed change (shadow, additive, upright byte-identical)

1. `classify_native_path_role` and `identify_source_wall_junctions_and_roles` gain `page_rotation: int | None = None` (the page's effective /Rotate). When `page_bounds` is passed:
   - `0`: today's test, unchanged.
   - `90`: the same test on the displayed lowest edge, which for a quarter turn is `rect.x1 >= y0 + 0.82 * height` (same bounds, same constant; the identity above, verified against `page.rotation_matrix`). The bounds must start at the page origin, as `native_page_frame` requires; otherwise band membership is not established (next bullet).
   - `None`, 180, 270, or any value that is not an exact int in (0, 90, 180, 270): band membership cannot be established. Rows that already have a typed negative that does not depend on the band (green, dashed, excluded layer, diagonal bridge) keep it; a row that would otherwise take a positive role (exterior owner, attached structure, explicit wall layer) becomes `ROLE_UNKNOWN` (ABSTAINED). No silent skip and no silent identity. This matches the live seam, which fails closed on 180 and 270.
   - `page_bounds=None`: no test, as today. A row without a `rect` keeps today's behaviour (test skipped).
2. `tools/run_native_exterior_path_ownership.py` passes `page_rotation` from `pb_native_page_frame.effective_pdf_rotation(page)`, catching `NativePageFrameUnresolved` as `None`. This works on every page, unlike a trace-bound frame (94 of the 129 rotated pages have an ABSTAINED trace and no frame).
3. The one existing title test passes `page_rotation=0`; the default now means "not established", which is the point of the change. No other importer exists.

**Alternatives rejected.** Importing `pb_page_frame_shadow` (guarded). Reusing #4652's `page_derotation_matrix` (candidate traces only; couples this PR to a Draft; a third frame vocabulary). Dropping the geometric band (loses the only title-block cut on the no-footprint fallback path of the tool). Converting rows with PyMuPDF inside the classifier (the module is a pure function of dict rows; keep it that way). Replacing the fixed 18 percent prior by title-block evidence (`pb_page_title_authority`) is a different change with its own note.

## 4. Tests to write first (AGENTS.md matrix)

Segment-splitting invariance is not a property of today's semantics (one row, lowest edge): splitting a row that straddles the band changes the result for its halves. Recorded as an observation and decision 3, not changed here.

**What changed.** `pb_source_native_wall_role_and_junction_shadow.py`: `_in_title_band` (the frame-aware test), `page_rotation` on `classify_native_path_role` and on `identify_source_wall_junctions_and_roles`, and the public constant `TITLE_BAND_START_FRACTION` (0.82, value unchanged). `tools/run_native_exterior_path_ownership.py`: `_page_rotation_for_roles` (the production `effective_pdf_rotation`; `NativePageFrameUnresolved` becomes `None`), passed to the report and also recorded in the payload as `title_band_page_rotation`, so a fail-closed run is visible in the JSON (the one addition beyond section 3). `tests/test_source_native_wall_role_and_junction_shadow.py`. Nothing else.

**Behaviour as built.** Rotation `0`: the old expression, unchanged. Rotation `90`: the displayed lowest edge is native `x1`; the bounds must be finite, anchored at the page origin (within the frame seam's 1e-6 pt) and positive in height, otherwise band membership is unestablished. Anything that is not an exact `int` 0 or 90 (`None`, 180, 270, `True`, `False`, `90.0`, `"90"`, out of range) is unestablished. Unestablished: a placed row that would take a wall role becomes `unknown`; green, dashed, excluded-layer and diagonal rows keep their role; a neutral row is not claimed as title block either. No bounds or no readable rect: no test, as before. Recorded, not changed: at rotation 0 a zero or negative bounds height still skips the test (the module's own behaviour; no caller passes such bounds).

**Synthetic proof.** 81 tests in the role test file (11 before). Rotation 0 equals a frozen copy of the old rule on 4,000 random rows (random layers, paints, dashes, odd or missing rects, owner and attached sets, five bounds including degenerate and non-origin). On real PyMuPDF pages at /Rotate 0 and 90, four sheet sizes (native portrait and landscape), the new label equals the old rule applied to the row mapped with `page.rotation_matrix`; 180 and 270 pages abstain; one displayed drawing authored upright or on a rotated sheet gets the same roles per row. Look-alike negatives fail on the old rule (a native-bottom wall row is title block there; the real displayed band is missed). Scale, translation (along and across the band), input-order, far-content, replay (two hash seeds) and no-mutation checks; the report stays `ABSTAINED` with `can_issue_area=False`; an import-graph test pins the tool as the module's only importer outside tests; the tool is exercised end to end on a synthetic rotated PDF at /Rotate 90 and 180. 33 single-line mutants of the module and the tool (fraction, comparison, `x1` versus `y1`, each rotation branch, bool and float rotations, each bounds clause, the demotion, the pass-through, the tool wiring, including the old behaviour behind the new signature): 33 killed, 0 survived.
