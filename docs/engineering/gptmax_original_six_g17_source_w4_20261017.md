## Actual mechanism examined

The original physical G17 producer detects 300-DPI painted opening faces and jamb
ends. The default W2/W3/W4 structural wall graph draws independent 144-DPI
raster-visible segments. Those different namespaces cannot authenticate each
other by primitive string equality. The existing producer
`SourceVisibilityProducer._proven_raster_opening_flank_boxes` nominates some
opening flank ink into the ordinary wall capture only when the physical opening
has an area-bearing label. This is a NOMINATION gate, not a source role proof.
Globally lifting the gate previously changed host/representative IDs and
customer retention; this PR does NOT touch that gate.

The repository already has a source-positive nonpublishing alternate reader,
`build_opening_local_g17_wall_shadow`, which re-resolves one opening's original
source selectors, authenticated parent IDs and pixel/DPI receipts, checks
original unchanged native image ink, and independently replays the original
W2→W3→W4 algorithms on just its three exact source segments per sealed flank.
It reports candidate records from the actual normal 2.5 pt snap and exact
zero-snap comparison. Neither result is a complete page-wide structural
universe or source-positive physical equivalence.

## Engineering implementation

`tools/diag_gptmax_six_opening_local_g17_source.py` creates exactly ONE new
source producer from the actual SHA-pinned Lot16 PDF selected page 3. It
reissues original wall/opening composition, canonical voids, signed quantity
and independently verified customer projection. It selects all **six** genuinely
unhosted original physical openings by current host receipts, without passing
any benchmark identities or opening labels to the selector.

For each, it reuses original producer
`build_opening_local_g17_wall_shadow` with its own signed observation selector;
reports exactly two sealed face-pair/end flanks, all original source observation
and parent addresses, independently painted source support, normal/exact W2
graph outcomes, retained W3 types and every existing source-local W4 identity.
A 300-DPI W4 candidate is NOT a 144-DPI structural owner. Original source
scope, page, revision, snapshot, every source receipt and signed customer rows
must remain unchanged.

No production code, physical object selector, source nomination, raster
safety bound, 2.5pt snap, 4pt threshold, original source PDF, V2 frozen
truth, quantity or commercial output changes. Test negatives cover malformed
source ownership, snapshot tampering, stale physical ID, unsupported ink,
duplicate W4 identities and attempted authority grants. Original GitHub
workflow performs source SHA check and fresh page-3 producer replay.
