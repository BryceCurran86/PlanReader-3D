# Original-source opening opposition and receipt retention

## Architecture review

Observed: `SourceVisibilityProducer.native_unstroked_fill_evidence` authenticates
the complete original native PDF paint support. `PhysicalOpeningAuthority.prove_existence`
retains the candidate and emits ABSTAIN when that opposing paint role explains
its entire support. `tools/diag_opening_wall_face_preservation.source_face_report`
contains bindings only for positive existence claims. The default
`compare_source_face_reports` consequently reports a missing claim even when
the original unhosted hypothesis has legitimately become opposed evidence.

Inference: source-retention failures in unrelated workflows need separate
explanations for unexplained loss and fully source-proven opposition. A change
in an aggregate count cannot provide either explanation.

Implemented secondary audit: `scripts/gptmax_source_opposition_retention.py`
accepts original immutable PDF bytes and base/head source reports. Every shared
binding must remain exactly equal. Every prior authenticated frame payload
must remain exactly equal. No added claim is approved. A missing claim can be
explained only if it had neither host nor frame proof, and the original native
source authority freshly retains its exact six-line candidate with complete
fill opposition. The existing physical-geometry identity helper recomputes
the previous opening address from freshly authenticated source lines; an
unrelated representative or borrowed opposed candidate fails.

The strict default comparator is unchanged. Inputs are never mutated. The
secondary audit allows no hypothesis deletion, physical-nonexistence proof,
new host, count or quantity publication. It imports the existing evidence
vocabulary and physical identity function rather than defining a second one.
