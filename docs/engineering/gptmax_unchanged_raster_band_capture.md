# Unchanged terminal raster-band capture — architecture report

Observed on main `e6d780a0`: `SourceVisibilityProducer.augment_with_raster_visible_segments`
renders ordinary lines at 144 DPI. `detect_axis_aligned_raster_segments` rejects
fat/branched connected components. Isolated 300-DPI opening primitives are
deliberately separate. `OpeningHostBindingProducer.publish_binding` reaches
`_resolve_raster_source_band_host_from_records`, which requires both an ordinary
source primitive and its actual local W4 owner at each authenticated flank end.
The source label dimension producer independently owns figured area; publication
in `publish_live_opening_area_quantities` also requires the real host receipt.

Inference: a continuous source-solid terminal interval whose core and entire
centerline reproduce exactly in the full render can supply missing ordinary
geometry without consuming or interpreting overlaid native paint. A changed
pixel is a cut, never evidence to bridge. This may supply geometry but cannot
itself establish structural role, physical equivalence, a host, scale, or area.

Proposed: a bounded perception detector over exact four-edge boxes from the
existing raster primitive compiler. Retain only maximal terminal intervals
with solid original cores/centerlines and exact image/full RGB equality. Reuse
the existing 4-pt observation minimum; never extend a run. Exclude intervals
already covered by ordinary source lines within the same band. Put supplemental
observations in a separate frozen identity namespace, preserve every ordinary
observation/index and reauthenticate registration and both render hashes.
Nomination is restricted to every independently G17-proven source opening with
a complete source-authenticated figured dimension product. Its numeric value
never chooses a segment or changes a threshold. All raw primitives and unmeasured
openings remain retained; this path cannot assert discovery exhaustiveness or
opening count. Ordinary end contact/coverage suppresses redundant nomination
only, using existing producer pixel/snap bounds; it does not grant a host.
The existing complete source-owned W2/W3/W4 and G17 host contracts decide whether
the resulting object closes; no direct host/canonical/quantity assignment.

Expected abstentions: competing W4 owners, incomplete local source coverage,
missing wall roles/viewport/equivalence, inconsistent frames, changed or blank
pixels, incomplete candidate universes and unowned dimensions remain blocked.
First validate source capture in isolation, then replay the actual original
production composer and publication. If the object remains blocked, do not
present the source observation as quantity progress or repeat the same probe.

Benchmark observations excluded from implementation: source drawings and their
known quantities do not determine constants, ordering, host choice or thresholds.
Original PDFs, frozen V2 truth/evaluator/denominators/tolerances, the 20,000 input
cap, W10, scale authorities and commercial writers stay untouched. Existing
Maryborough FIRM controls and original Lot16 host/quantity receipts must survive.

The published snapshot legitimately grows when source observations are added.
Host/frame receipt IDs include that snapshot and therefore rekey. The existing
strict receipt comparator must remain unchanged: a same-count assertion cannot
approve rekeys. Separately compare every prior source W4 member, positive source
path/edge ancestry and whole-wall frame geometry; retain every old physical and
quantity identity. Any actual source geometry, host or frame loss blocks merge.
The narrower implementation is intended to close one additional figured-area
opening, rather than globally reissue additional unrelated wall observations.
