## Inference and bounded implementation

A reproducible, independently checked input-coverage primitive is a necessary
prerequisite to a future source-role orchestration change. It does not establish
that such a change is safe or that supporting documents may be ignored.

`tools/gpt3_native_source_execution_coverage.py` consumes the existing typed
native source authorities, one original page at a time. It verifies the exact
original digest, file identity, positive page inventory, revision, original
page marker, complete page observation lineage and snapshot membership. Each
page producer and store is released before the next page is decoded.

The JSON-safe receipt retains hashed native snapshot/observation identities and
the existing aggregate `SourceDecodeCoverageRecord`. It contains no raw source
text, filenames, geometry or measurement. Native decode coverage is complete;
semantic enumeration and decision scope stay unknown. Measurement, takeoff,
commercial and benchmark grants are always false. Verification re-ingests the
actual original PDF and compares the complete reconstructed receipt. Recomputing
a public checksum cannot validate a modified, partial or borrowed receipt.

Missing, aliased, changed, wrong-digest or wrong-page-count originals fail.
Failed pages, borrowed page/revision identities, absent page markers and receipt
tampering fail. Same-byte inode replacement fails as well as content mutation.
Blank and image-only pages may have valid input coverage; that never means their
physical or semantic content has been interpreted.

## Validation and limits

The existing `produce_all_source_roles` exposes
`record_native_source_input_coverage=False`; its CLI forwards the option only
when `--record-native-source-input-coverage` is explicitly present. It builds
and independently re-verifies each native receipt before/after the actual
producer subprocess and retains a private source-file identity witness across
that subprocess. The existing role report carries the input-only receipts and
their separate `native_source_input_coverage_verified` status. Source mutation,
same-byte inode replacement and failed native input halt this opt-in run.

This input audit cannot set `source_role_coverage_verified`, create an empty
quantity seal, enable customer rows, clear an actual producer failure or change
the incomplete exit code. Default commands and report keys remain unchanged.
All genuine per-document quantity seals are still required by the existing
cross-role composer. Successful input coverage alongside unavailable quantity
seals therefore remains `SOURCE_ROLES_INCOMPLETE`.

The focused tests cover native blank/text/vector and rotated originals,
image-only input, JSON round trip and deterministic independent replay,
coordinated tamper with a recomputed checksum, page/revision borrowing, source
replacement, failed native decoding and bounded producer/store lifetimes.
Existing source-observation, source-preflight and archived Lot16 signed-fixture
regressions run alongside them in Python 3.13 and 3.14 CI.

Protected original validation is separate from source-free CI. No new source
quantity, verified customer output, full-suite score or release permission
follows from this bridge. Existing runner/reporter defaults, quantity issuers,
signed rows, frozen evaluator/reference/maps, 20,000 primitive cap and 2.5-point
snap are not modified. No expected quantity or benchmark identity entered the
implementation. A later orchestration integration needs its own explicit
source-execution and independent signed/customer acceptance proof.
