## 1. Observed repository behavior (VERIFIED only, synthetic fixtures)

### 1.1 Library ground truth (PyMuPDF 1.28.0)
- VISUAL (rotated) space: `page.rect` (extents swap at 90/270), `rotation_matrix` output, `get_pixmap` output, and `get_pixmap(clip=)` input.
- RAW (unrotated, CropBox-origin-normalised) space: `get_drawings`, `get_text` words/dict/blocks and line `dir`, `search_for`, `get_image_rects`; `get_text('dict')['width','height']` and `page.mediabox` are unscaled by UserUnit while `page.rect`, drawings and words are scaled.
- `page.rect * page.derotation_matrix` equals the raw extent only when UserUnit == 1. With UserUnit 2 and rotation 90 it gives (0,-842,2382,842) instead of (0,0,2382,1684) (re-run here). A scale-safe raw extent is `page.rect` with width/height swapped when `page.rotation` in (90, 270).
- `page.rotation` normalises -90 -> 270 and 450 -> 90, reads 0 for 45, 91 and -1 (note: 45 and 91 still swap `page.rect`, -1 does not; re-run here), and resolves /Rotate inherited from the Pages node (page-dict key null, `page.rotation` 90; re-run here). /Rotate is optional (default 0). Render ground truth for non-orthogonal entries (finalizer, marker-centroid render, PyMuPDF 1.28.0): /Rotate 135, 179 and 224 render as 180 while `page.rotation` reads 0 and `page.rect` keeps its size; 45, 89 and 91 render as 90; 1 and -1 render as 0. `page.rotation` and the rect orientation therefore cannot reveal the rendered rotation for every spelling, so the /Rotate entry itself (own or inherited) has to be inspected.
- No `pb_*.py` reads `mediabox`/`cropbox` (grep empty). A rect at (100,100,300,200) reads back identically at 0/90/180/270.

### 1.2 Hypothesis outcomes
- **H1 CONFIRMED (mechanism).** `extract_native_page` takes width/height from `pdf_page.rect` (pb_vector_geometry_v130.py:529) while segments (:386) and words (:495) are raw. `SourceObservationProducer.ingest_native_pdf_bytes` persists that pair as the `native_pdf_page` observation (pb_source_observation_authority.py:641). Mixed pair in 44/44 runs at 90/270, consistent at 0/180. Real-source page counts: section 4.
- **H2 CONFIRMED, with corrected mechanism.** `_native_line` reads raw `dir` (pb_viewport_segmentation.py:576-577); `_wrapped_continuation` (:594, :598) needs horizontal lines stacked downward in raw y. Result: 0 tails vs 1 at rot 0 in 18/18 note-bearing matrix runs (3 tails in a 4-line-note fixture) for content authored upright on the visual sheet. Mechanism differs per rotation: at 90 PyMuPDF splits the vertical note into separate 1-line blocks, so no run can form whatever the direction test says; at 270 the direction test fails (horizontal=False on all lines); at 180 lines stack upward (gap < 0). A rotation-aware direction test alone would therefore NOT fix 90. The false "DETAIL SHEET"-style tail anchor is admitted (extract_view_title_anchors:672-674), so the #1138 defect returns. No run showed over-suppression (fails open). The shipped test (tests/test_viewport_wrapped_note_tail_ownership_v1.py:59,166) calls `set_rotation` after raw authoring, so it is vacuous for upright-authored rotated content.
- **H2 is not specific to /Rotate (adversarial fixture S1).** The same raw stream on a /Rotate 0 portrait page (sideways-drawn sheet; dims consistent) gives tails 0, the false "DETAIL SHEET" anchor, and the title-block frame bound as FLOOR PLAN. The defect is text reading-orientation; /Rotate only correlates with it.
- **H3: rotation-causation REFUTED; source-specific cause UNVERIFIED.** `_TITLE_SHAPE_RE` (:188) is an anchored closed whitelist and rotation-independent. Details: section 4.
- **H4 CONFIRMED (settled first).** Wall-authority boundary checks compare RAW content to ROTATED dims: `_source_page_segments` returns `native["width"/"height"]` (pb_physical_wall_candidate_authority.py:667-668), fed to `_on_rect_boundary(point, 0, 0, page_width, page_height)` at :753 and in `_viewport_scope_boundary_reason` (def :821; page-dim call :830-837). The AGENTS.md firm seams (wall length, measurement input, figured dimension, page-scale authority, viewport scale binding) contain no page-geometry comparisons. Rotation reaches them only through scope, `scope_complete` and which scale bars are visible.

## 2. Inference (not observed directly)

- The defect splits into three classes that need different fixes (high confidence): (a) extent/space mismatch, determined by /Rotate (H1, H4, derived extents, border test, scale bbox); (b) text reading-orientation of anchors and notes, which /Rotate correlates with but does not determine (H2, caption-below, title-block zone); (c) render/raster clip space (visual vs raw).
- A dims-only fix (swap width/height when rotation in 90/270) addresses (a) but not (b) or (c).
- Neither "visual" nor "raw" is the reading frame for every page: derotating to visual space restores family V but degrades family U and S1/M1 pages. A single global contractual space is a false dichotomy for the orientation-dependent heuristics; it is only needed for extents and clips (medium-high, executed on fixtures).
- Real-source behavior depends on whether it is vector/CAD, a scan, or hybrid. UNVERIFIED (low confidence).
- Most rotated-page paths fail closed. Fail-open sites: the page-scale bbox (conflict masking), sheet-border / title-block frame acceptance, the wall-fill frame exclusion, and the wall-edge test (missed edge ends, V). Downstream effect on a published quantity is unproven.

## 3. Proposed change (shadow only, nothing promoted)

### 3.1 Alternatives
- **A. Canonicalise once at ingest** (derotate raw content to visual space). Changes native observation geometry and every id on rotated pages; regresses U/S1-type pages; effectively a re-ingest = authority-promotion review. Not shadow-compatible.
- **B. Carry page-frame facts as typed evidence; consumers abstain later.** Additive, no id change at rot 0, reuses the `_text_clip_reasons` precedent.
- **C. Reject rotated pages at ingest.** Smallest but discards pure scans that work, changes commercial output, hides the defect.
- **D. Shadow oracle: run the UNMODIFIED consumers on a derotated in-memory twin and diff outputs** (evidence only, result never published, original source hash retained, guarded by CropBox == MediaBox else abstain reason, run on a copy). Avoids re-implementing private heuristics (a de facto second resolver) and does not edit consumers.

### 3.2 Recommendation: B for ownership + D for measurement, decomposed by defect class
- (i) **Extent descriptor** (class a). Fields: `rotation` (= `page.rotation`), `user_unit`, `visual_extent = page.rect`, `raw_extent` = `page.rect` with width/height swapped when rotation in (90,270) (NOT `rect * derotation_matrix`), mediabox/cropbox recorded as notes. No exact-float mapping: any later coordinate mapping must use exact double arithmetic on raw floats, not `fitz.Matrix` (float32-quantised; 1.2e-4 error vs `_COORD_TOL = 1e-6` at pb_physical_wall_candidate_authority.py:115, re-run here; note `page.rect` itself is float32-rounded, so edge tolerance on non-integer sheets needs its own fixtures).
- (ii) **Orientation evidence** (class b): per anchor / per line reading direction taken from the text's own `dir`, not from /Rotate. Must report sideways rot-0 pages (S1) and mixed-orientation pages (M1) as divergences; list viewports whose anchor direction is not the page-reading axis.
- (iii) **Shadow diff** via alternative D, first on ONE consumer: the wall page-edge test (pb_physical_wall_candidate_authority.py:753 / :830-837), the H4 site. Other consumers added afterwards.
- Descriptor is a provenance record, NOT an `EvidenceAtom` or `QuantityEvidence`, and carries no measurement authority. Status reuse: `EvidenceResolutionStatus` only marks frame coherence (RAW/CANDIDATE coherent; CONFLICT or ABSTAINED otherwise). A test asserts none of the AGENTS.md firm-seam modules can import it.
- Coordinate-space vocabulary: reuse the existing `CoordinateSpace` enum (pb_figured_dimension_evidence.py:49: PDF_POINTS / RASTER_PIXELS) and note `COORD_SPACE_PDF_POINT` (pb_elevation_calibration_v177.py:34) and `coordinate_space` (pb_canonical_building.py:108). "Raw vs visual" is carried as a separate ORIENTATION attribute next to `CoordinateSpace`, not a new space enum.
- Abstention vs divergence: a mismatch between `raw_extent` and the legacy recorded pair (the rotated `page.rect` width/height, pb_vector_geometry_v130.py:529) is a typed DIVERGENCE FLAG, not an abstention (it is expected at every 90/270 page). Reserve ABSTAINED/CONFLICT for degenerate or conflicting boxes, unresolvable `page.rotation`, or missing ownership inputs. /Rotate absent = 0 (no abstention); inherited /Rotate resolves via `page.rotation`; Rotate values 45/91/-1 are library-normalised: report a `nonstandard_rotate_spelling` note rather than ABSTAINED unless the owner chooses fail-closed (Q3); pin the PyMuPDF version in the test. CropBox larger than MediaBox is a note, not CONFLICT.
- Ownership: signature takes explicit inputs `describe_page_frame(page, *, document_id, source_sha256, revision, page_no)`; abstains if any is missing; id = `stable_contract_id` over those plus frame facts (no wall-clock values).
- Later, separate reviewed PRs (not this report): per-consumer fixes following the `_to_visual_bbox` precedent, or fail-closed on `rotation != 0` at the fail-open sites with existing reason codes (`PHYSICAL_WALL_CANDIDATE_SCOPE_BOUNDS_UNRESOLVED`, `PHYSICAL_SCALE_SCOPE_UNAVAILABLE`, following `_text_clip_reasons` at pb_pdf_text_integrity_authority.py:1116). Either changes commercial output on rotated pages.
- The scale-bbox conflict masking (section 1.3) is an existing contract defect ("conflicting evidence must abstain") that stays live through PR 1. It needs a separate authority-promotion review track (Q4), independent of the descriptor.

### 3.5 Id impact if later phases add a mapping (for the review)

- "Emit new keys only when `rotation != 0`" makes the payload schema rotation-dependent and leaves rot-0 sideways pages (S1) on legacy ids. A design choice for the promotion review; it requires golden-ID tests for both branches.

So the masking is still present in the existing code and would not occur if the bbox were compared in the declared native frame, but no scale behaviour was changed and the fix belongs to the separate fail-closed review track.

### 8.10 Independent verification and finalizer fixes
Four verifier lenses (contract and scope audit; independent geometry and determinism; CI parity; shadow proof) and a mutation hardener reviewed the first implementation. Every reported issue was independently reproduced before it was fixed or rejected.

Fixed (each with tests that fail without the fix):
1. **Non-orthogonal /Rotate rounded to 180 gave a wrong RAW frame (major).** /Rotate 135, 136, 179, 181, 224, -136 render as 180 in MuPDF while `page.rotation` reads 0 and the rect keeps its size, so the descriptor published rotation 0, wrong by 180 degrees, as a coherent RAW frame; a square page with /Rotate 91 hides the rect swap the same way, and the same holds for an inherited non-orthogonal entry. Reproduced by rendering a marker and comparing quadrants. Fix: any own or inherited (parent-chain walk, depth-bounded and cycle-safe) /Rotate entry that is not an exact orthogonal integer is CONFLICT with `page_frame_rotate_entry_not_an_orthogonal_integer`; an own orthogonal entry overrides an inherited one. The finalizer also found that `_nonstandard_rotate_entry("inf")` raised `OverflowError` (breaking the "never raises" contract); non-finite entries are now CONFLICT.
2. **The page object was not checked against `page_no` (minor).** Page 2's extent was published under `page_no=1`. Fix: CONFLICT (`page_frame_page_object_number_does_not_match_page_no`) when `page.number` is an int and differs from `page_no - 1`. The page-to-source-hash binding cannot be verified by the descriptor and is documented as the caller's responsibility.
3. **Ownership text with a lone surrogate (minor, real defect broader than reported).** The verifier reported `to_json()` raising; the finalizer found that `describe_page_frame` itself raised `UnicodeEncodeError` (in `stable_contract_id`) for such a `document_id` or `revision`. Fix: ABSTAINED with `page_frame_ownership_text_not_utf8_encodable`; the text is never stored.
4. **Diff-script scope statement (minor).** The script docstring and section 8.4 now state that "current" is the page-boundary predicate with viewports switched off, and that `cross_check: mismatch` is legitimate on pages with viewport structure. The finalizer reproduced a real mismatch: the 2383.94 x 1683.78 cm-authored sheet at /Rotate 270 (an earlier `BOUNDS_UNRESOLVED` end masks a page-edge end in the real consumer). The earlier report text claiming every fixture page matched was wrong and is corrected in 8.4.
5. **Report accuracy (minor).** Test counts and file list in 8.1 and 8.7 updated; scratch-only numbers (648 and 16,000-case sweeps, 300-box 1.5 ulp cross-check, 6,600-case edge sweep, four-sheet shadow-proof SHA) are labelled as scratch and the narrower committed tests named; the per-label equivalence claim is scoped (8.5): column (a) is not per-label rotation-equivalent on cm-authored sheets (8 / 8 / 4 label mismatches, re-run), column (b) is on all fixtures (0 mismatches; now a committed test).
6. **Hygiene.** `.ruff_cache/`, a root `__pycache__/` and `planreader_data/` (ignored test-run artefacts) were deleted from the worktree; ruff was run with `--no-cache`.

Test changes: `test_page_frame_shadow_v1.py` 191 -> 220 (the old "-1 is benign" test was replaced by stricter non-orthogonal-entry tests, plus page-number, UTF-8 and inherited-walk tests); the read-only-surface whitelist in the hardening file gained the read-only attribute `page.number`; one parametrised test (x3 sheets) was added to the diff hardening file for the per-label equivalence scope.

## 9. Choices open to review (made by the lead/implementer; none is required by the approved decisions)
1. **Coherent status = RAW** (not CANDIDATE): the descriptor is a recorded page-metadata observation (source-observation records default to RAW); never CORROBORATED. Missing ownership, unreadable/degenerate metadata, unresolvable rotation or invalid UserUnit = ABSTAINED; contradictory metadata or a revision that does not match the producer definition = CONFLICT.
2. **Unit axis** is the literal `"pdf_points"`, not an imported `CoordinateSpace`: importing `pb_figured_dimension_evidence` drags in firm-seam modules. A test asserts the literal equals `CoordinateSpace.PDF_POINTS.value` and that the two frame-space values do not collide with the unit vocabulary. The value means UserUnit-scaled PyMuPDF points.
3. **`FrameSpace` enum** (module-local, two members) for the space axis.
4. **Native extent definition**: box (0, 0, w, h) in CropBox-origin-normalised, UserUnit-scaled PyMuPDF points; w/h = `page.rect` swapped for 90/270. A non-zero `page.rect` origin is CONFLICT.
5. **Tolerances**: `CROSS_CHECK_ULPS = 4` (observed 1.5 in the implementer sweep, 1.9 in the verifier's independent sweep) and `EDGE_QUANTISATION_ULPS = 8` (observed 3; the lead proposed 4 and it was changed to 8 after the 6,600-case sweep showed 3 ulp). Both are multiples of the float32 ulp of the largest participating magnitude, derived from the rounding model, never tuned to a benchmark.
6. **Diff location** `scripts/page_frame_wall_boundary_shadow_diff.py` (section 8.1 for the reasons) and its use of the consumer's private predicates; its cross-check makes signature drift fail loudly.
7. **Two shadow columns** (extent only; extent plus derived bound) rather than silently applying the bound.
8. **Every non-orthogonal /Rotate entry (own or inherited) = CONFLICT (fail closed)** rather than note-only. The alternative from the original report was a `nonstandard_rotate_spelling` note. The first implementation made only 45/91/90.5 CONFLICT (via the rect-orientation cross-check) and kept -1 as RAW with a note; the finalizer pass tightened this to every non-orthogonal entry because MuPDF's rounding can render 135 as 180 with an unchanged rect and `page.rotation` 0. The cost is that a benign -1 or 1 is also CONFLICT. MuPDF's rounding of these spellings may change across PyMuPDF versions; the related tests are skipped unless PyMuPDF is 1.28.0.
9. **Revision verified, not trusted**: the descriptor recomputes the producer's revision id.
10. **Descriptor carries no per-wall or per-end state**; those live only in the diff output.
11. **Page-object number is checked against `page_no`** (CONFLICT on disagreement) when the page object exposes an int `number`; duck-typed pages without one are not rejected.
12. **Non-UTF-8-encodable ownership text = ABSTAINED** with its own reason code, and the text is not stored.
13. **An unreadable or NaN MediaBox with a finite `page.rect` still gives RAW** (with `boxes_unreadable` / `orientation_cross_check_skipped` notes) because the cross-check cannot run. This is fail-open-with-note, not fail-closed; flagged by the hardener and left open for review.

## 10. Limitations
- **Synthetic-only validation, and the real-rotated-PDF gate.** Everything here is validated on hand-built fixtures. No real source PDF with genuine /Rotate 90/180/270 was available or used; second-hand counts from any real project are not validation. Before the descriptor is wired into live physical-wall or scale authority, such a PDF must be obtained and the shadow comparison rerun. The tolerances (section 8.5) in particular have not been checked against real CAD exports. The same gate is stated in the module docstring, the diff script docstring and the PR body.
- Only the page-edge test of one consumer is diffed, with viewports switched off (`all_viewports=[]`; the fixtures do carry a "FLOOR PLAN" caption, but the diff does not pass the segmented viewports to the predicate); the viewport segmentation path, which is itself rotation-affected (section 1.3), is not exercised, and "current" in the diff is the page-boundary predicate only, so `cross_check: mismatch` is legitimate on pages with viewport structure (section 8.4). The consumer's predicate also inherits its pre-existing gaps (an OR over four infinite edge lines that ignores whether the point is inside the page); the descriptor's `point_on_edge` does not have that gap but is not used by the diff, to keep the comparison on the existing predicate.
- Not addressed by design: text and anchor orientation (defect class b), wrapped-note tails, title-block zones, render/raster clip space (class c), the scale-bbox masking (section 8.9), border and fill frame tests, schedule parsing at rotation. The sideways rotate-0 and mixed-orientation cases remain known open defects.
- Behaviour pinned to PyMuPDF 1.28.0 (`requirements.txt`): MuPDF's own /Rotate rounding, `page.cropbox` y-flip and UserUnit treatment could change in other versions. Python 3.14 (in the CI matrix) was not available locally; the new code uses no 3.13-only features but was only run on 3.13. The full `tests/` suite was run in four file-level shards (section 8.7); sharding does not preserve cross-file ordering or shared global state. Two failures there are unrelated to this change (one identical on the PR base, one a wall-clock flake that passes alone). It was not run on Python 3.14.
- `edge_quantisation_pt` is a diagnostic bound derived from float32 rounding. It is not a tolerance authority and nothing consumes it. Evidence for k is 6,600 synthetic cm-authored ends (scratch) plus a committed deterministic 6,000-stroke sweep.
- `page.mediabox` and `page.cropbox` use inconsistent frames (mediabox absolute y-up and unscaled; cropbox y measured down from the MediaBox top); they are recorded as diagnostics under frame-naming fields and are never the extent authority. Non-orthogonal /Rotate values are not representable and are CONFLICT or ABSTAINED.
- Probe scripts from the investigation are not preserved (section 0); the claims they supported in sections 1-2 (H1-H3, use-site table, 88-run matrix) are not re-verified by PR 1.
- Stable-ID non-change for unrotated pages follows from construction (no existing payload, observation identity or dataclass was touched and no existing file was modified), and the shadow proof in 8.6 supports it for extractor and wall-candidate outputs; a full before/after golden-ID run across a rot-0 corpus was not performed.
- **Base drift.** The worktree branch is based on 1b429843; `origin/main` has since moved to 48034e66 (PR #1142). The change is additions only (8 new files, 0 modified), so a rebase cannot conflict, but a plain `git diff origin/main` shows three spurious deletions until the branch is rebased. The page-frame tests plus the repo-wide enumerator suites pass on an overlay of the new files on 48034e66 (section 8.7).
- **Unreadable boxes are fail-open with a note.** If `page.mediabox` / `page.cropbox` are unreadable or NaN while `page.rect` is finite, the orientation cross-check cannot run and the frame is RAW with `boxes_unreadable` and `orientation_cross_check_skipped` notes (section 9, item 13).
- **Indirect or exotic /Rotate objects are CONFLICT**, even when `page.rotation` would resolve them, because the entry text cannot be verified as an orthogonal integer.
- **Descriptor-to-document binding.** The descriptor checks the revision id against the producer definition and the page number against `page.number`, but cannot verify that the page object came from the document whose `source_sha256` was passed.
