# The production Docker image installs the Tesseract OS binary; pytesseract
# above is the Python bridge used by DrawingOCREngine on Linux/Render.
# RapidOCRBackend (pb_portable_raster_ocr_authority.RapidOCRBackend) is
# implemented and tested, but its dependencies -- rapidocr, onnxruntime,
# and their own transitive deps -- are DELIBERATELY NOT listed here.
#
# Deployment status: optional/local backend only. This file's own header
# documents memory-optimization for the Render free tier (512MB); the
# ~30MB of bundled ONNX detection/classification/recognition models plus
# an onnxruntime process footprint have not been sized against that
# budget or explicitly approved for the production deployment target.
# RapidOCRBackend.is_available() correctly reports False wherever these
# packages are not installed (Render production included, as things
# stand today), and PortableRasterOCRProducer.from_environment()'s
# auto-selection only prefers RapidOCR when is_available() is genuinely
# True -- it does not assume or claim RapidOCR is present. On a real
# Windows development machine with `pip install rapidocr onnxruntime`
# done manually, it works today; it is not silently claimed available
# anywhere it has not actually been installed.
#
# Promoting this to a listed, always-installed production dependency (or
# to some other deployment shape -- an extras group installed on demand,
# a separate OCR microservice, etc.) is a deployment-architecture decision
# for whoever owns the Render memory budget, not something to do
# unilaterally by adding it here.
